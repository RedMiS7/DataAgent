# 结论带依据

日期：2026-11-10

对应优化计划 2 的第 7 步：2.4 结论带依据。

## 做了什么

**结论的格式**
- 模型写的结论改为 JSON：
  ```json
  {"judgement": "一句判断",
   "points": [{"claim": "说法", "evidence": [{"query": 1, "rows": [0, 1], "columns": ["期间", "退货率"]}]}],
   "advice": "可以执行的建议"}
  ```
  `rows` 是行号，从 0 开始；`rows` 或 `columns` 留空，表示整张表的行或列。
- 分析题的提示词要求：
  - `points` 写 2～4 条，每条至少有一条依据；
  - 依据覆盖前提（两期的总体数字）、主要来源（贡献最大的几项），适用时再加对照；
  - 说“没有单一主因”时，用贡献分布作为依据；
  - 3.1 完成之前，主要来源由模型自己写 SQL 算。
- 查询题：一句结论加 1 条依据，没有 `advice`。没有查数就能回答的问题（例如解释口径）仍然直接用中文回答。
- 格式说明放在新文件 `backend/app/agent/conclusion.py` 里，三处共用：
  - 分析计划的汇总提示词（`planner.py` 的 `SUMMARY_PROMPT`）；
  - 不走计划的单 Agent 分析（`pipeline.py` 的 `ANALYSIS_ANSWER_RULE`）；
  - 查询模式（`pipeline.py` 的 `QUERY_ANSWER_RULE`）。
- 给模型的查询结果加上编号：
  - `run_sql` 的返回结果在查询模式下也带 `query_index`（以前只有分析模式带）；
  - 分析汇总时给模型的查询结果，每行前面加行号（从 0 开始）。

**程序处理**（`backend/app/agent/conclusion.py`、`pipeline.py`）
1. 解析 JSON，逐条检查依据。以下情况都算错：
   - 查询编号不存在；
   - 行号超出这条查询的行数；
   - 列名不在查询结果里；
   - 要点没有依据；
   - 缺少判断或要点。

   回复前后多了文字或代码块标记，可以容忍。`"查询1"`、单个行号、单个列名这类写法也能读。
2. 有错时，把原来的结论、每条错误原因、全部查询结果（带编号和行号）交给模型重写一次。重写用单独的模型（`build_rewrite_model`），超时 45 秒，调用名记为 `rewrite`。
3. 重写后仍有错：
   - JSON 能读出结构：去掉不对的依据，结论标为未通过校验（`checked: false`），页面展示全部查询；
   - 两次都读不出结构：展示模型第一次写的原文，和以前一样处理文字里的 `[查询n]`，展示全部查询。
4. 回答的 `summary` 由结构生成：
   - 分析题：判断、每条“- 说法[查询n]”、“- 建议：……”。`[查询n]` 来自依据。
   - 查询题：只有判断。依据在页面上另外展示。

   对话历史、复制结论、评测的检查点和旧的回答都还用 `summary`，所以都不受影响。
5. 展示哪些查询：
   - 分析题：展示依据引用的查询；
   - 查询题：展示依据引用的第一条有数据的查询。

   依据没有通过校验时：分析题展示全部查询，查询题展示最后一条有数据的查询。
6. 每条依据带一张小表：程序从查询结果里取出引用的行和列，最多 10 行。

## 为什么做

以前的结论是一段文字，靠 `[查询n]` 标出来源，只能指到整条查询，指不到具体的行和列。用户看不出一句话是从哪几个数来的。2.1 删掉了用代码核对数字的逻辑后，结论里的数字更是没有任何依据可查。

改成每条要点带引用以后：
- 程序能检查引用是否存在，不存在就让模型重写；
- 页面能在每条要点旁边列出它用到的数据；
- 1.7 的评委模型能拿“说法 + 依据数据”判断说法是否成立。

只检查引用存不存在，不检查数字和说法是否相符。后者容易误判，2.1 刚因此删掉了这类代码，交给 1.7 做。

## 有什么用

- 每条要点都能展开看到它依据的几行数据和 SQL，结论可以核对了。
- 查询模式下，模型答完又多查一条时，展示的表跟着依据走，不会和结论对不上。这个问题是 2.1 留下的。
- 评测能统计依据的完整率和重写率，满足计划 2 完成标准里的“分析题的每条要点都有依据”。也能回答计划里待定的“DeepSeek 用 JSON 输出结论的解析失败比例”。
- 1.7 有了可以评判的输入。

## 已知的影响

- 三处结论提示词都改了，结论的写法会变。查询题的结论现在是 JSON 里的判断，比以前的一句话可能长一些。
- 查询题平均慢 2～3 秒（输出变长）。依据出错时多一次模型调用，最多 45 秒，可能超出问答原来的总时限。
- 两次都读不出结构时展示模型原文。原文可能是不完整的 JSON，会带着括号显示。
- 模型可能引用错行：行号从 0 开始，可能差一位。程序只能发现越界，发现不了引错。
