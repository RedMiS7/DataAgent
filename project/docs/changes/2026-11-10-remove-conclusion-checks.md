# 删除用代码校验结论的逻辑

日期：2026-11-10

对应优化计划 2 的第 5 步：2.1 删除所有用代码校验结论的逻辑。

## 做了什么

**结论直接用模型写的**
- `backend/app/agent/pipeline.py`：
  - `_summarize`：模型写了结论就原样使用，来源记为 `model`；模型没写结论时才用模板，来源记为 `template`。以前结论超过 120 字、不含数字、含 SQL 字样，或者有一个数字在查询结果里找不到，都会被换成模板，并发出 `summary_fallback` 状态。这些判断和这个状态都删掉了。
  - `_finish_analysis`：删除"这些数字未能在查询结果中核对"警告。只展示结论引用的查询；结论没有引用时，展示全部查询（和以前一样）。
  - 删除 `_uncited_sources`。以前结论里有数字来自没被引用的查询时，会把那条查询也补进展示列表。
  - `_text_answer`：删除"这些数字没有查询依据"警告，不再需要对话历史，参数里去掉了 `history`。
  - 查询模式：结论里如果有 `[查询N]` 标记，按它选展示的表，再把标记从句子里去掉（查询模式只展示一张表，标记没有可以指向的地方）。
- `backend/app/analysis/attribution.py`：固定归因流程里模型写的结论不再校验，写了就用。

**展示哪张表**
- `backend/app/agent/answer.py` `select_execution`：参数从结论文字改成结论引用的查询编号。
  - 有引用：展示引用的查询里第一条有数据的；都没有数据时，展示引用的第一条。
  - 没有引用：展示最后一条有数据的查询；都没有数据时，展示最后一条查询。
  - 以前是拿结论里的数字去每条查询的结果里找，找到哪条就展示哪条，找不到时展示第一条有数据的。

**删除的代码**
- `answer.py`：`verify_summary`、`unverified_numbers`，以及只给它们用的 `_numbers_in_text`、`_candidate_strings`、`_row_numbers`、`_number_is_in`、`NON_DATA_NUMBER`、`DISPLAYED_NUMBER`、`UNIT_SCALE`。
- `backend/app/agent/__init__.py`：不再导出 `verify_summary`。
- `frontend/src/components/chat/ReasoningPanel.tsx`：警告步骤里去掉 `summary_fallback`。

**保留的**
- SQL 安全校验、隐私拦截、`decline_request`、时间范围和 SQL 日期不一致的提示、"查询次数已用完"的提示。
- `normalize_citations`、`strip_citations`：分析结论的引用标记和历史消息还在用。
- 评测里对分析题的判分早在第 3 步（1.4）就不看"数字未核对"了，这次没有改评测代码。

**测试**
- `backend/tests/test_answer.py`：删除 4 个 `verify_summary` 的测试。
- `backend/tests/test_pipeline.py`：
  - 删除 `unverified_numbers` 的测试（12 个）；
  - `select_execution` 的 3 个测试按新规则重写；
  - 新增：结论带引用时按引用选表，标记从句子里去掉；没有引用时展示最后一条有数据的查询；
  - 新增：4 种以前会被换成模板的结论现在原样保留（含算出来的差值和"30天"、不含数字、超过 120 字、含"SQL"字样），并且不再发 `summary_fallback`；
  - 新增：模型没写结论时用模板（查询模式和分析模式各一个）；
  - 分析题：结论里有查不到的数字时不再有警告；没被引用的查询不再补进展示列表；引用多条查询时按编号顺序展示。
- `backend/tests/test_direct.py`：两个"没有查询依据"的测试合成一个，改为直接回答原样展示、没有警告。
- `backend/tests/test_planner.py`：两个测试改为汇总结论原样保留、只展示被引用的步骤。

## 为什么做

用代码核对结论里的数字，误判很多：
- 模型算出来的差值、占比，查询结果里本来就没有；
- "最近30天""前10名"这类数字不是查出来的值；
- 单位换算和四舍五入的写法太多，规则覆盖不全。

结果是正确的结论被换成"gmv为 9072501.5。"这样的模板句，或者带上"未能核对"的警告，用户看到的反而更差。真正写错的结论，这套规则也拦不全。

所以这一步先把代码校验全部删掉，结论回到模型写的原样。结论对不对，后面由 2.4（结论带依据）和 1.7（离线评委模型）来管。

## 有什么用

- 查询模式的结论不再被模板替换。小样本里 4 道指标题，改之前 3 道是模板结论，改之后 4 道都是模型写的结论（见下面的对比）。
- 分析结论和直接回答不再带误报的警告。
- 少了约 130 行校验代码和一个前端状态。

## 已知的影响

- 查询模式下，模型看不到查询编号，提示词也没有要求它写引用，所以实际上展示的总是最后一条有数据的查询。如果模型在得出答案之后又多跑了一条查询，展示的表会是多跑的那条，和结论对不上。以前靠核对数字能选回正确的那条，现在不能了。这要等 2.4（结论带依据）来解决。
- 结论的长度和内容不再有限制。提示词要求查询模式的结论不超过 60 个字符，模型不遵守时也会原样展示。
- 结论里的数字现在没有任何检查。i02 就是例子：查询返回的是退款金额和 GMV 两列，3.93% 是模型自己算的。在 2.4 和 1.7 完成之前，结论的正确性只能靠人工看和评测的行比对。
