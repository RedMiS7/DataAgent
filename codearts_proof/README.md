# codearts_proof/ —— 华为云码道使用证明

证明项目由华为云码道（CodeArts）深度参与开发的过程材料。

## 目录规划

```
codearts_proof/
├── 01_prompt/          # 核心功能的 AI 交互对话与 Prompt 截图
├── 02_generate/        # 代码生成过程记录
├── 03_refactor/        # 重构过程记录
├── 04_debug/           # 排错过程记录
└── README.md
```

图片命名建议：`序号_模块_动作.png`，例如 `01_prompt_sql_validate.png`。

## 1. 核心功能开发的 AI 交互对话与 Prompt 截图

每张截图需能看清：提问内容、码道回复、生成结果。建议覆盖以下功能点：

- [ ] 问答主流程编排（五步流程的接口与状态机）
- [ ] 语义层与向量检索（四集合的检索策略、提示词拼装）
- [ ] SQL 生成与自动修正（报错回灌、最多重试 3 次）
- [ ] SQL 安全校验（sqlglot 单条 SELECT 放行、危险函数拦截）
- [ ] Redis 缓存与限流（规范化 SQL 哈希、Lua 滑动窗口）
- [ ] 图表推荐规则
- [ ] 评测脚本与评测集设计
- [ ] 前端对话页与结果展示组件

每个功能点至少 1 组「Prompt → 生成 → 采纳/修改」的完整链路。

## 2. 代码生成、重构、排错的过程记录

### 代码生成
- [ ] 每个主要模块的首轮生成记录与最终代码差异说明
- [ ] 生成后人工修改点清单（改了哪里、为什么改）

### 重构
- [ ] 重构前的坏味道描述（如问答流程函数过长、SQL 校验与执行耦合）
- [ ] 码道给出的重构方案与采纳情况
- [ ] 重构前后对比（结构、可读性、测试是否仍通过）

### 排错
- [ ] 真实缺陷：现象、复现步骤、报错栈、码道分析结论、修复补丁、验证结果
- [ ] 建议至少 3 个案例，覆盖后端、前端、数据/检索
- [ ] 保留未被采纳的错误建议案例，说明人工判断依据（体现评审过程）

## 材料规范

- 截图保留完整窗口或对话框，不要只截一行文字；必要时用红框标注关键位置。
- 每张截图配一行说明：时间、模块、目的、结论。
- 敏感信息（密钥、手机号、内网地址、真实订单数据）打码。
- 若提供原始对话日志，去除个人信息后放入本目录并在索引中登记。
- 建议在本文件末尾维护一张「材料索引表」：文件名 | 类型 | 对应功能 | 说明。
