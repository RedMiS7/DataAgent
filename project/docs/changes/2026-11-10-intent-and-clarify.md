## 做了什么

**意图识别取代路由**
- `backend/app/agent/router.py`：
  - 原来的路由调用改为意图识别，一次调用输出 JSON，同时包含 `route` 和意图的各个字段。
  - 提示词保留原来的路由规则，加上每个字段怎么写、追问怎么沿用上一轮、怎么合并对反问的回答。
  - 系统提示词后面附上语义层的【指标目录】和【可以按取值筛选的字段】。这部分每个问题都一样，能用上模型的前缀缓存。用户消息里附上这次检索到的字段、匹配到的实体值和【上一轮的理解】。
  - 回复解析不了时重试一次。两次都不行时，按查询模式或用户选的模式继续，不带意图，并记日志。
  - 超时从 15 秒改为 30 秒，因为包含了重试。
  - 回复里只有 `route`、没有任何意图字段时，只用来选模式，不当作意图。
  - 删除了 `parse_route`，由 `intent.parse_intent` 代替。
- `backend/app/agent/intent.py`（新增）：
  - 意图的结构：指标（用户的说法、语义层的指标名、自定义算法、候选）、时间（原话、是否需要时间）、对比期、维度、筛选、结果形式、缺少的信息和模型给的反问。
  - 解析时宽松处理：取值不对的字段丢掉，不报错。
  - 程序检查（`check_intent`），每项的做法：

    | 字段 | 检查 |
    | --- | --- |
    | 指标 | 名字或别名在语义层里能找到就改成标准名；说法是几个指标的别名，或模型列出了几个候选时，算歧义；语义层里没有的指标保留模型写的算法说明；查询模式下一个指标都没有，算缺失 |
    | 时间 | 用现有的时间解析检查原话。解析不了算有问题；“最近”这类没说具体时间段的词，按没说时间处理 |
    | 对比期 | 解析不了就丢掉，按默认对比期 |
    | 维度 | 字段在语义层里不存在就去掉字段名，保留说法 |
    | 筛选 | 字段是实体字段时，取值要在数据库里找得到。“抖音渠道”能对上“抖音”；对不上时算有问题，并给出最接近的几个值，没有相近的值就给前几个实际取值。读不到取值、或取值超过读取上限时不检查 |
    | 结果形式 | 前 N 名没写 N，按前 10 名，并写明假设 |
    | 缺少的信息 | 非空就反问，用模型写的反问和选项 |

  - 反问：每次只问第一个问题，带 2～4 个选项。轮数按历史里最近连续的反问回复来数，最多 2 轮。之后按默认值处理，并列出假设，例如“‘退货’按‘退货率’统计”。
  - 时间范围：以意图里的时间原话为准，交给现有的时间解析算出日期。没说时间、并且问题需要时间时，写明“未指定时间，按最近 30 天统计”。
  - “我理解为”的一行文字和交给查数 Agent 的说明。
- `backend/app/agent/pipeline.py`：
  - 每个问题都做意图识别，包括用户手动选了模式的问题。手动选的模式不变。
  - 直接回答不检查意图。直接回答时发现需要查数、改走查询的，也不检查。
  - 检查不通过并且还没问满 2 轮时，返回 `clarify` 状态，不查数。
  - 通过后：
    - 用意图里的时间算时间范围；
    - 把“对这个问题的理解：……”加进查数 Agent 的问题，分析模式加在每一步的时间说明后面；
    - 发出 `understood` 状态，显示“我理解为：……”。
  - 回答反问时，检索用“原问题 + 回答”，时间先看回答再看原问题，查数 Agent 收到的问题是“原问题（补充：回答）”。
  - 新增 `build_router_model`（意图识别用自己的模型，测试可以单独替换）和 `load_catalog`（读语义层的指标、字段和实体字段的取值，读不到时不检查）。
- 回答结构（`backend/app/api/schemas.py`）：

  - 意图失败、拒答时，`intent` 为空。

## 为什么做

以前路由只判断用查询、分析还是直接回答，问题本身怎么理解全靠查数 Agent 自己猜，用户看不到它是怎么理解的。问题有歧义或者缺信息时，它也只能挑一种理解直接查，查错了用户还不知道错在哪里。

把意图写成结构以后，程序能对着语义层检查：指标在不在、有没有歧义、筛选值存不存在、时间解析不解析得了。有问题就先问用户，没问题就把理解显示出来，同时交给查数 Agent。评测也能按字段统计意图准不准，以及该问的问了没有、不该问的问了没有。

意图识别和路由合成一次调用，是为了不再多加一次模型调用。手动选了模式也调用这一步，因为意图在任何模式下都要用。

## 有什么用

- 用户能看到“我理解为：时间：上个月；指标：退货率”，理解错了可以马上纠正。
- 有歧义、筛选值不存在、没说要看什么的问题，会先反问，并给出可以点的选项。最多问两轮，之后按默认值回答，并说明做了哪些假设。
- 没说时间的问题不反问，回答里写明按最近 30 天统计。
- 评测多了意图准确率、漏问率、多问率三项基线。
- 2.3 可以直接用意图检查 SQL。

## 已知的影响

- 每个问题多一次模型调用，查询题平均多约 3 秒。以前手动选模式时不调用路由，现在也调用。
- 意图识别的提示词比原来的路由提示词长，输入 token 增加。指标目录放在系统提示词里，能用上缓存。
- 检查规则偏严时会多问。比如模型把一个说法列成了几个候选，或者实体值读取有上限、值不全时，都可能误判。多问率就是用来看这个的，跑完全量后再调。
- 路由评测现在也带指标目录，和以前的路由评测结果不能严格对比。
