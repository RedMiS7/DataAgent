# 不需要查数的问题直接回答，追问继承时间

日期：2026-11-08

## 做了什么

这是[问答流程优化方案](../问题记录/问答流程优化方案.md)的第 3 步，同时修了第 0 步基线里发现的"追问没有继承时间"。

后端：

- `backend/app/agent/router.py`：路由从两类改为三类，新增 `direct`（直接回答），用于解释口径、问能做什么、打招呼、改写或解释之前的回答。规则写明：只要回答需要对话里还没出现的数字就不能选 `direct`，拿不准时选查数。提示词新增了几条 `direct` 示例，刻意没有照抄评测题。对话记录里直接回答的轮次标为"助手（直接回答）"。
- `backend/app/api/schemas.py`：新增 `RouteChoice`（`query`、`analysis`、`direct`），`RouteInfo.chosen` 用它；回答状态和历史状态新增 `text`。
- `backend/app/agent/pipeline.py`
  - 路由为 `direct` 时，用一个不带工具的 Agent 回答，输入是对话记录、指标口径和表摘要。如果它判断其实需要查数，会输出"【需要查数】"，流程自动改走查询模式，路由理由里注明"回答时发现需要查数"。
  - 查询和分析模式下，模型没有查询、只给了文字回答时，不再记为失败（原来是"模型没有调用 run_sql 工具"），状态记为 `text`。系统提示词新增第 12 条，允许不需要查数时直接回答。
  - 新增 `_text_answer`：直接回答里的数字必须来自对话记录里的回答、检索到的参考资料或问题本身，否则加警告"这些数字没有查询依据：……"。
  - `text` 状态的回答展示检索到的指标口径。
  - 追问判断 `FOLLOWUP_PATTERN` 增加了几种开头和说法："按""只看""加上""也""同样""上面""刚才""这个/这些"（不含"这个月"）、"把这/那/上面/刚才"，以及句中的"拆一下""拆开""细分"。被判为追问且没说时间的问题，会继承上一轮的时间，检索时也会带上上一个问题。

前端：

- `frontend/src/types.ts`、`src/lib/modes.ts`：新增 `text` 状态和 `RouteChoice`；新增 `routeLabel`，自动判断显示"查询""分析"或"直接回答"。
- `frontend/src/components/chat/AnswerCard.tsx`、`src/styles.css`：`text` 状态的回答按段落显示（保留换行），不用大标题样式；不显示"用分析模式重新回答"按钮。

测试：

- 新增 `backend/tests/test_direct.py`，16 个测试：路由接受 `direct`、直接回答的标签、直接回答不执行 SQL 并展示口径、改写时沿用对话里的数字不报警、凭空的数字会报警、需要查数时改走查询、查询模式下的口径问题直接回答、新的追问说法和时间继承。
- `backend/tests/test_failure.py`：`no_answer` 的用例改为模型什么都没回答。只回答文字的情况现在属于直接回答。
- 前端：`modes.test.ts` 新增 2 个测试，`failure.test.ts` 补充了 `text` 状态的判断。

## 为什么做

基线里，"GMV包不包括运费？""你能查哪些数据？"会直接报错"模型没有调用 run_sql 工具"；"把这个结论写成一段话发给老板"会重新查一遍，而且没有继承"上个月"，查成了最近 30 天，给老板的数字是错的。"按渠道拆一下"也因为没被识别成追问，查成了最近 30 天。

## 有什么用

- 解释口径、问能力范围、改写之前的结论，都能直接回答，不用等查数，也不会报错。
- 改写之前的回答时，沿用已经查到的数字，不会重新查出一个不一样的数。
- 判断错了也有退路：直接回答时发现需要查数，会自动改为查询。
- "按渠道拆一下""只看直播渠道""加上 GMV"这类追问会继承上一轮的时间。
