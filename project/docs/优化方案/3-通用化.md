## 3.1 通用的指标变化拆解

**新工具 `metric_breakdown`**

参数由模型填写。指标的算法来自语义层的文字口径，或者题目里给出的定义：

| 参数 | 内容 |
| --- | --- |
| `numerator` | 指标（比例类指标就是分子）：`from_sql`（表和关联）、`expression`（度量表达式，例如 `SUM(r.refund_amount)`）、`time_column`（按哪一列归属时间）、`where`（筛选条件）、`dimension`（维度表达式，例如 `c.name`） |
| `denominator` | 可选，比例类指标的分母，字段和 `numerator` 相同 |
| `current`、`previous` | 本期和对比期，默认取意图里的时间范围和对比期 |

**程序处理**
1. 按参数生成两期的分组查询。生成的 SQL 经过现有的 SQL 安全校验，包括"只能查检索过的表"。
2. 返回结果：
   - 两期的总值；
   - 每个维度值的两期数值、增量、占总增量的比例，按增量排序；
   - 比例类指标：分子和分母各自的增量和占比，以及每个维度值自己的比值变化。
3. 结果像普通查询一样存进 `context.executions`，可以作为 2.4 的依据引用。

**替换旧功能**
- 删除 `backend/app/analysis/attribution.py`，以及 `backend/app/agent/tools.py` 里的 `refund_breakdown`。
- 删除侧边栏里单独的"异动归因"页面（`frontend/src/pages/AttributionPage.tsx`，入口在 `frontend/src/components/Sidebar.tsx`、`frontend/src/App.tsx`）和它专用的接口 `POST /attribution/return-rate`。归因能力保留：用户在对话里问"为什么……"，走分析模式，调用 `metric_breakdown`，回答按 2.4 带依据。
- 评测里的固定归因组（`evaluate_attribution`）删除。

**涉及文件**
- `backend/app/agent/tools.py`
- 新增拆解工具的模块
- `backend/app/api/routes.py`
- `frontend/src/pages/AttributionPage.tsx`、`frontend/src/App.tsx`、侧边栏

**测试**

- 比例类指标：分子、分母的增量和每个维度值的比值变化，和手算一致。
- 参数里用到没检索过的表、写了非 SELECT 语句时被拦截。

## 3.2 归因按贡献排序

**改法**
- 在分析模式的规划提示词里写明归因步骤：
  1. 先算两期的总指标，判断前提是否成立；
  2. 调用 `metric_breakdown`，按增量和贡献占比排序；
  3. 最大一项的占比低于 30% 时，写"没有单一主因"；
  4. 能查到的话，和过去几期的波动范围比较。
- 提示词里不写具体的指标名、维度名。

**涉及文件**
- `backend/app/agent/planner.py`

**测试**
- 两个数据集的归因题，拆解步骤都按贡献排序。
