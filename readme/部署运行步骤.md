# 部署运行步骤

## 方式一：本地一键启动（推荐用于演示）

```bash
# 0. 前置：安装 Docker Desktop、Python 3.11+、Node 20+
cd <仓库根目录>

# 1. 安装依赖并拉起中间件
bash readme/install.sh

# 2. 填写密钥
vi project/.env

# 3. 初始化业务库
cd project
docker compose exec -T mysql mysql -uroot -p"$MYSQL_ADMIN_PASSWORD" < data/schema.sql

# 4. 生成并导入模拟数据（8~10 张表，几十万~百万行）
python data/generate.py --rows 500000 --out data/seed.csv
python data/load.py --source data/seed.csv

# 5. 构建语义层与向量索引（四个集合）
python -m backend.app.cli init_semantic
python -m backend.app.cli build_index --collections schema_items,metrics,qa_cases,entity_values

# 6. 启动后端
uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 --reload

# 7. 另开终端启动前端
cd project/frontend && npm run dev
```

访问 `http://localhost:5173`（前端）与 `http://localhost:8000/docs`（接口文档）。

> 以上命令路径对应 `project/` 的规划结构，实际文件名不同处以 `project/README.md` 为准，并同步修改本文件。

## 方式二：Docker Compose 整体启动

```bash
cd project
cp .env.example .env   # 填写密钥
docker compose up -d --build
docker compose logs -f app
```

## 方式三：云端部署（华为云）

1. **RDS for MySQL 8.0**：创建实例，业务库与应用库分开；为 Agent 创建只读账号并配置列权限或脱敏视图。
2. **DCS for Redis**：创建实例，将连接信息写入 `.env`；确认安全组放通。
3. **ECS**：部署 Qdrant 与应用后端；Qdrant 数据目录挂载持久化磁盘。
4. **大模型 API**：开通服务，配置 endpoint、模型名与密钥，设置调用额度。
5. **安全组**：仅对外开放前端入口；MySQL / Redis / Qdrant 不暴露公网。
6. **初始化**：在 ECS 上执行数据导入与索引构建，然后启动应用服务。

## 验证跑通（演示前自检）

| 检查项 | 操作 | 期望结果 |
| --- | --- | --- |
| 服务健康 | `curl http://localhost:8000/healthz` | 返回 200 |
| 首个问数 | 问“上个月哪个商品退货率最高？” | 表格 + 图表 + 结论 + 口径 |
| 查看 SQL | 点击“查看 SQL” | 展示可读 SQL |
| 多轮追问 | 继续问“那上上个月呢？” | 沿用上文条件，时间范围随之变化 |
| 归因分析 | 问“退货率为什么涨了？” | 按商品 / 渠道 / 物流下钻 |
| 安全拦截 | 输入诱导写操作的提问 | 被 SQL 校验拒绝并给出提示 |
| 缓存加速 | 重复问同一问题 | 第二次响应明显更快 |
| 降级 | 停止 Redis 或 Qdrant 后重问 | 仍返回答案（可能变慢或检索降级） |

## 停止与清理

```bash
cd project
docker compose down            # 停止容器，保留数据卷
docker compose down -v         # 连数据一起清除（慎用）
```

## 常见问题

- **端口冲突**：修改 `docker-compose.yml` 端口映射与 `.env` 中对应端口，保持前后端一致。
- **初始化脚本重复执行**：导入脚本需支持幂等或先清库，避免演示前数据翻倍。
- **大模型超时**：检查网络出口与密钥额度；P95 目标小于 15 秒，超时需在日志中可见。
- **索引缺失**：Qdrant 索引可随时重建，原文保存在应用库，重建不丢数据。
